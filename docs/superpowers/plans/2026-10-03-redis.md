# Redis implementation plan

**Goal:** Complete issue #1 slice 4: cross-pod locks and optional shared API metadata caching. App-to-app messages use RabbitMQ.

**Architecture:** Separate bounded lock/cache connections. A managed task detects
lock outages and reconnects with runtime backoff; failures remain latched for the
coordinator. Leases use existing keys and atomic token checks, renew automatically,
and cancel protected futures when ownership becomes unknown. Cache failures call
the supplied API loader. No Redis publisher or subscriber.

**Stack:** redis-rs, Tokio, UUID, Lua; isolated local Redis integration tests.

- [x] Update configuration/contracts tests first; remove notification settings,
  dependency, and Pub/Sub channel. Add `EXCHANGE_METADATA_CACHE_ENABLED` (default
  true), allowing the optional connection to be disabled completely.
- [x] Implement `src/redis/connection.rs`: bounded commands, cancellation-safe
  ownership, sanitized errors, separate connections, latched required failure,
  capped recovery, quiesce and close. No automatic command replay.
- [x] Implement `src/redis/lease.rs`: `SET NX PX`, UUID token, five-second acquisition
  window, owner-checked Lua verify/renew/release, 30-second TTL, 10-second renewal,
  at most one second per lease command, local expiry tracking, protected-future
  cancellation, and task abortion on drop. Quiesce preserves existing renewals.
- [x] Implement `src/redis/cache.rs`: TypeScript-compatible keys/JSON/TTL,
  fail-open `get_or_load`, no caching failed API responses, no cache connection
  when disabled. API business calls remain supplied by the future worker.
- [x] Test with `tests/redis.rs`: contention across independent managers, unrelated
  accounts, owner replacement, renewal, expiry, unknown acquisition response,
  outage/idle recovery, cache fallback/disable/TTL, cancellation, and shutdown.
- [x] Update docs and issue scope; run full tests, formatting, Clippy, and review.

Runtime composition with RabbitMQ follows in slice 5. Durable Mongo claims remain
the execution deduplication mechanism; Redis leases cannot fence external side
effects already accepted remotely, or guarantee exclusivity across Redis data loss.

Verified: all 57 tests passed, including seven isolated Redis integration tests
and the MongoDB replica-set test. Formatting, Clippy, and diff checks passed.
Review found a release/renewal cancellation race; a regression reproduced it and
passed after the fix. The follow-up review found no remaining important issues.
